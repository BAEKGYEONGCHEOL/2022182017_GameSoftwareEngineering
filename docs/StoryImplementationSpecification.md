# 검은 항로 스토리 구현 명세

문서 버전: 1.0  
작성일: 2026-09-28  
대상 프로젝트: C++ / OpenGL 기반 싱글플레이 2.5D 쿼터뷰 RPG  
문서 목적: Codex가 기존 프로젝트에 퀘스트, 대화, 문서, 이벤트와 영속 상태를 직접 구현할 수 있도록 스토리를 데이터 중심 명세로 제공한다.

## 1. 문서 사용 규칙

- 이 문서는 현재 프로젝트의 스토리 구현 기준이다.
- `GameDevelopmentGuidelines.txt`의 세계관과 주제를 유지한다.
- 이미 구현된 플레이 흐름과 이름인 `노크티스`, `에레보스`, `공허종`, `마지막 항로`를 보존한다.
- 모든 퀘스트, 인물, 지역, 문서와 이벤트는 이 문서의 영구 ID로 참조한다.
- 화면에 표시하는 한국어 이름과 내부 ID를 분리한다.
- 내부 ID는 저장 데이터 호환성을 위해 한 번 사용한 뒤 변경하지 않는다.
- 확정되지 않은 세부 설정은 코드 상수에 직접 고정하지 않고 외부 데이터로 분리한다.
- 대화 선택지는 선악 점수를 직접 표시하지 않는다. 선택의 결과는 NPC 상태, 지역 상태, 자원과 후속 사건으로 보여준다.
- 현재 프로토타입 범위는 프롤로그와 제1장 초반이다. 후속 장은 콘텐츠 확장 시 순서대로 구현한다.

## 2. 작품 핵심

### 2.1 한 줄 소개

인간과 공허종의 전쟁으로 고립된 항성계를 탐험하며, 두 종족의 기억을 함께 지닌 주인공이 전쟁의 시작과 자신의 탄생에 관한 진실을 확인하고 전쟁을 끝낼 방법을 선택하는 이야기다.

### 2.2 중심 주제

> 전쟁은 괴물과 싸우는 과정에서 시작되지만, 상대를 괴물로 규정하는 순간 끝낼 수 없게 된다.

### 2.3 플레이어에게 남겨야 하는 질문

1. 생존을 위해 저지른 폭력은 어디까지 정당화되는가?
2. 명령을 실행한 개인과 명령을 만든 조직은 각각 어떤 책임을 져야 하는가?
3. 진실을 공개해 더 큰 혼란을 일으키는 일과 거짓 평화를 유지하는 일 중 무엇을 선택할 것인가?
4. 적의 기억과 감정을 이해하게 된 뒤에도 같은 방식으로 싸울 수 있는가?
5. 평화를 위해 포기해야 하는 힘과 안전은 어디까지 감수할 수 있는가?

## 3. 세계 설정

### 3.1 시대

- 기준 연도: 서기 2874년
- 인류는 고대 외계 공간 연결 장치 `심연문`을 이용해 여러 항성계로 진출했다.
- 심연문 실험으로 미지의 생태권과 연결되면서 인간과 공허종의 접촉이 시작됐다.
- 최초 접촉의 공식 기록은 공허종의 기습으로 되어 있지만 실제로는 인간 연구진이 공허종의 기억망을 강제로 채취한 사건이 먼저였다.
- 전쟁으로 통신 중계망과 주요 항로가 파괴되어 식민지, 정거장과 함선이 고립됐다.

### 3.2 공허종

- 공허종은 생체 기술과 집단 기억망을 사용하는 종족이다.
- 집단 기억망은 감정과 경험을 공유하지만 모든 개체의 의지를 완전히 통제하지 않는다.
- 전쟁 중 인간의 고통스러운 기억이 대량 흡수되면서 기억망 일부가 공포와 복수를 반복하는 상태로 변했다.
- 게임 초반의 포식체와 정찰체는 적대적이지만 일부 기억체와 이탈자는 의사소통할 수 있다.
- 공허종 전체를 하나의 도덕적 주체로 표현하지 않는다.

### 3.3 인간 세력

| 내부 ID | 표시 이름 | 목표 | 핵심 문제 |
|---|---|---|---|
| `faction_union_remnant` | 항성연합 잔존군 | 질서와 항로 복구 | 민간 희생과 강제 징발을 정당화한다. |
| `faction_helix` | 헬릭스 기업체 | 공허종 기술 독점 | 전쟁과 주인공의 탄생에 직접 책임이 있다. |
| `faction_return_cult` | 귀환교단 | 인간과 공허종의 결합 | 평화적 교감파와 강제 융합파가 대립한다. |
| `faction_frontier` | 변경 생존자 연합 | 지역 공동체의 생존 | 장기 전략보다 당장의 자원을 우선할 수 있다. |
| `faction_void_collective` | 공허종 기억망 | 기억망의 생존과 복구 | 인간 전체를 침입자의 기억으로 일반화한다. |
| `faction_void_severed` | 공허종 이탈자 | 집단 기억에서 독립 | 인간과 공허종 양측에게 배신자로 취급된다. |

## 5. 전역 스토리 상태

다음 상태는 퀘스트 enum 하나에 모두 넣지 않고 별도의 월드 상태 저장소에서 관리한다.

```yaml
story_state:
  current_chapter: prologue
  main_quest_id: mq_00_last_route
  main_quest_stage: wake

  truth_fragments: 0
  civilian_survivors: 0
  void_survivors: 0
  evidence_preserved: 0
  evidence_destroyed: 0

  human_alignment: 0
  void_alignment: 0
  reconciliation: 0

  noctis_repaired: false
  erebos_secured: false
  abyss_gate_status: dormant

  flags: {}
  npc_states: {}
  region_states: {}
```

### 5.1 누적 수치 규칙

- `truth_fragments`: 전쟁의 시작과 실험체 계획에 관한 유효 증거 수
- `civilian_survivors`: 실제 구조 완료된 인간 민간인 수
- `void_survivors`: 살려 보내거나 구조한 비적대 공허종 수
- `evidence_preserved`: 원본 상태로 보존된 기록 수
- `evidence_destroyed`: 파괴하거나 조작한 기록 수
- `human_alignment`: 인간 기술과 인간 세력에 의존한 선택 누적값
- `void_alignment`: 공허종 능력과 기억망에 의존한 선택 누적값
- `reconciliation`: 양측의 생존과 대화를 위해 비용을 지불한 선택 누적값

수치는 선악 점수가 아니다. 엔딩 조건과 일부 NPC 반응을 결정하는 근거로만 사용한다.

## 7. 프롤로그: 마지막 항로

### 7.1 퀘스트 정의

```yaml
id: mq_00_last_route
display_name: 마지막 항로
chapter: chapter_00
start_region: region_noctis_interior
end_region: region_erebos_dock
required: true
```

### 7.2 단계

| 단계 ID | 목표 문구 | 시작 조건 | 완료 조건 | 다음 단계 |
|---|---|---|---|---|
| `wake` | 선내 단말기를 조사하라. | 새 게임 시작 | 단말기와 `E` 상호작용 | `find_core` |
| `find_core` | 기관 구역에서 항법 코어를 찾아라. | `wake` 완료 | 항법 코어 근처 도달 | `secure_core` |
| `secure_core` | 공허종을 처리하고 항법 코어를 확보하라. | 적 활성화 | 필수 적 제거 후 코어 획득 | `return_cockpit` |
| `return_cockpit` | 조종석으로 돌아가 항법 장치를 복구하라. | 코어 획득 | 조종석 상호작용 | `fly_signal` |
| `fly_signal` | 구조 신호 지점으로 이동하라. | 함선 조종 시작 | 목적지 범위에서 `E` | `dock_erebos` |
| `dock_erebos` | 에레보스에 도킹하라. | 목적지 도달 | 전환 완료 | `complete` |
| `complete` | 구조 신호의 근원을 조사하라. | 에레보스 도착 | 제1장 시작 이벤트 | 없음 |

### 7.3 선택 조사

#### 승무원 기록

```yaml
id: doc_noctis_crew_01
interaction: inspect
flag_on_read: read_noctis_crew_01
state_changes:
  truth_fragments: +1
  evidence_preserved: +1
```

표시 내용:

> 공식 보고서는 공허종이 먼저 포문을 열었다고 적혀 있다. 개인 기록의 마지막 문장은 다르다. “표본이 깨어났다. 우리가 먼저 연결했다.”

#### 반복되는 구조 신호

```yaml
id: event_noctis_echo_signal
flag_on_complete: inspected_echo_signal
state_changes:
  void_alignment: +1
```

출력 순서:

1. “살려 주세요. 문을 열어 주세요.”
2. 같은 문장이 동일한 호흡과 간격으로 반복된다.
3. 통신 분석 결과 인간 성대가 아닌 선체 생체 조직에서 발생한 신호임이 드러난다.

정답이나 적대 여부는 프롤로그에서 확정하지 않는다.

## 8. 제1장: 침묵한 피난선

현재 프로젝트의 첫 레벨은 이 장의 첫 번째 임무다.

### 8.1 메인 퀘스트

```yaml
id: mq_01_silent_ark
display_name: 침묵한 피난선
region: region_erebos_deck_01
recommended_play_time_minutes: 10
```

### 8.2 레벨 목표

1. 훈련용 펄스 소총을 회수한다.
2. 연결된 방과 복도를 탐색한다.
3. 공허종 정찰체와 전투하며 경험치를 얻는다.
4. 레벨 2에 도달한다.
5. 스탯 포인트를 배분한다.
6. 생존자와 대화하고 현장 문서 세 개를 확인한다.
7. 함교 격리문을 열어 다음 구역의 상태를 확인한다.

### 8.3 단계 명세

| 단계 ID | 목표 | 완료 조건 |
|---|---|---|
| `collect_weapon` | 훈련용 펄스 소총을 회수하라. | `weapon_training_pulse_rifle` 획득 |
| `earn_experience` | 공허종 정찰체를 제거해 레벨 2에 도달하라. | `player.level >= 2` |
| `allocate_stats` | 획득한 스탯 포인트를 배분하라. | `player.stat_points == 0` |
| `investigate_deck` | 생존자와 문서를 통해 피난선의 상황을 확인하라. | 생존자 2명 대화 또는 문서 2개 확인 |
| `open_bridge_seal` | 함교 격리문을 열어라. | 격리 단말기 상호작용 |
| `complete` | 에레보스 제1갑판 확보 | 격리문 연출 완료 |

기존 레벨 완료 조건이 스탯 배분으로 끝난다면 `investigate_deck`과 `open_bridge_seal`을 후속 단계로 추가한다. 기존 전투와 레벨업 기능은 제거하지 않는다.

### 8.4 현장 문서

#### 문서 1: 격리 명령

```yaml
id: doc_erebos_quarantine_order
document_id: 0
flag_on_read: read_erebos_quarantine_order
state_changes:
  truth_fragments: +1
```

> 함장 명령. 감염 의심 구역을 봉쇄한다. 신원 확인이 끝나기 전까지 누구도 통과시키지 않는다. 구조 요청은 자동 응답으로 전환한다.

#### 문서 2: 의무관 관찰 기록

```yaml
id: doc_erebos_medic_observation
document_id: 1
flag_on_read: read_erebos_medic_observation
state_changes:
  reconciliation: +1
```

> 공허종 정찰체 하나가 무기를 버린 부상자를 지나쳤다. 공격하지 못한 것이 아니라 공격하지 않은 것처럼 보였다. 보고하면 기록이 삭제될 것이다.

#### 문서 3: 배급 기록

```yaml
id: doc_erebos_supply_manifest
document_id: 2
flag_on_read: read_erebos_supply_manifest
```

> 봉쇄 전 의료 구역 산소가 다른 구역으로 이전됐다. 감염 때문이라는 설명은 시간 기록과 맞지 않는다. 누군가는 승객을 살리기 전에 항해 장교들을 살리기로 결정했다.

### 8.5 생존자 대화

대화는 첫 대화와 반복 대화를 구분한다.

#### 난민 한

```yaml
id: dlg_han_erebos_first
speaker: char_han
condition: talked_han == false
on_complete:
  talked_han: true
```

첫 대화:

> 방송은 이 방이 안전하다고 했습니다. 문이 잠긴 뒤에야 거짓말인 걸 알았어요. 아이들은 다른 갑판에 있습니다. 군인보다 먼저 찾아 주세요.

반복 대화:

> 구조선이 오면 군인보다 먼저 아이들을 태워 주세요. 약속해 주세요.

#### 의무관 일리안

```yaml
id: dlg_illian_erebos_first
speaker: char_illian
condition: talked_illian == false
on_complete:
  talked_illian: true
```

첫 대화:

> 탄환보다 감염 공포가 더 많은 사람을 죽였어요. 서로를 먼저 의심했죠. 검사 결과가 나오기도 전에 격리문이 닫혔습니다.

반복 대화:

> 인간도 공허종도 같은 통로에서 죽었습니다. 전쟁은 시체를 구분하지 않더군요.

### 8.6 레벨 종료 사건

격리문이 열리면 안쪽에는 전투 흔적이 있지만 인간 시체와 공허종 시체가 서로 반대 방향을 향해 쓰러져 있다. 양측이 서로 싸우던 것이 아니라 같은 무언가를 피해 달아났다는 시각적 단서를 제공한다.

마지막 통신:

> 서윤: 함교에서 신호가 잡혔어요. 인간 구조 코드 아래에 같은 문장이 하나 더 있습니다. 공허종 대역입니다. 둘 다 우리에게 오지 말라고 경고하고 있어요.

다음 퀘스트 `mq_02_borrowed_memory`를 활성화한다.

## 9. 제2장: 빌린 기억

### 9.1 개요

에레보스 함교 신호를 추적하면 폐기된 통신 정거장에 도착한다. 정거장은 사람의 목소리로 구조 요청을 반복하지만 실제 송신자는 공허종 기억체 미라다.

### 9.2 핵심 선택

| 선택 ID | 행동 | 즉시 결과 | 후속 결과 |
|---|---|---|---|
| `choice_mira_destroy` | 미라를 공격한다. | 강한 전투와 공허종 능력 재료 획득 | 미라 동료 경로 폐쇄, 공허종 적대 증가 |
| `choice_mira_capture` | 헬릭스 격리 장치에 미라를 넣는다. | 헬릭스 보상 획득 | 제4장에서 미라가 실험 대상으로 등장 |
| `choice_mira_listen` | 무기를 내리고 기억을 공유한다. | 주인공의 실험 기억 일부 복구 | 미라 동료 경로 개방, 일시 최대 체력 감소 |

`choice_mira_listen`은 비용 없는 정답으로 만들지 않는다. 기억 공유 후 다음 임무까지 최대 체력 또는 회복 효율이 감소한다.

## 10. 제3장: 승자의 식량

고립 식민지 `케플러-19`에서 인간 정착민과 공허종 이탈자 집단이 같은 산소 정화 시설을 필요로 한다.

플레이어는 다음 중 하나를 선택하거나 충분한 자원과 기술을 확보해 공동 해결을 시도할 수 있다.

| 선택 | 필요한 조건 | 결과 |
|---|---|---|
| 인간 구역에 전력 공급 | 기본 선택 | 인간 생존 증가, 공허종 이탈자 사망, 잔존군 신뢰 증가 |
| 공허종 생태 구역에 전력 공급 | 미라 또는 공허종 해석 능력 | 공허종 생존 증가, 인간 난민 이탈, 잔존군 신뢰 감소 |
| 정화 시설 분할 | 수리 부품 3개 | 양측 생존 가능, 생산량 감소로 이후 자원 부족 발생 |
| 시설 완전 복구 | 라울 신뢰 2 이상, 희귀 코어 보유 | 양측 생존, 희귀 코어 소비, 후속 공동 거점 개방 |

공동 해결에는 탐험과 자원 비용이 필요하다.

## 11. 제4장: 최초의 문

헬릭스 연구시설에서 최초 접촉 원본 기록과 주인공의 실험 기록을 찾는다.

확정되는 사실:

1. 인간 연구진이 공허종 기억망에 먼저 강제 접속했다.
2. 접속 과정에서 수천 개체의 기억 구조가 손상됐다.
3. 공허종의 첫 공격은 손상된 기억망이 인간 연구진의 공포를 되돌려 보낸 사건이었다.
4. 헬릭스와 항성연합 지도부는 책임을 숨기기 위해 기록을 조작했다.
5. 주인공은 양측 기억망을 안정화할 목적으로 만들어졌지만 동시에 통제 병기로 설계됐다.

### 11.1 증거 처리 선택

- 즉시 전체 공개: 진실은 퍼지지만 인간 지역에 폭동과 지휘 체계 붕괴가 발생한다.
- 지역 지도자에게 단계적 공개: 피해를 줄일 수 있지만 일부 증거가 다시 은폐된다.
- 증거 봉인: 단기 질서는 유지되지만 헬릭스가 전쟁을 계속 이용한다.
- 조작 공개: 특정 세력의 지지를 얻지만 최종장의 화해 조건이 크게 낮아진다.

## 12. 제5장: 두 개의 명령

인간 함대는 심연문을 파괴하려 하고 공허종 기억망은 인간 항성 항로 전체를 차단하려 한다. 양측의 계획은 상대를 막을 수 있지만 고립 지역의 대규모 희생을 발생시킨다.

플레이어는 지금까지 확보한 동료, 지역과 증거에 따라 다음 임무 수단을 얻는다.

- 인간 함대 지휘 코드
- 공허종 기억망 진입 경로
- 변경 생존자 대피 항로
- 헬릭스 실험 자료
- 양측 공동 거점의 중계 장치

이 장에서 이전 선택의 결과가 병력 숫자보다 구조 가능 인원, 안전한 항로, 사용할 수 있는 대화 선택지와 보스전 단계에 반영돼야 한다.

## 13. 최종장: 검은 항로

### 13.1 최종 상태 평가

엔딩은 마지막 선택 하나만으로 결정하지 않는다.

```yaml
ending_inputs:
  truth_fragments: integer
  civilian_survivors: integer
  void_survivors: integer
  evidence_preserved: integer
  evidence_destroyed: integer
  reconciliation: integer
  trusted_companions: integer
  stable_regions: integer
```

### 13.2 엔딩

#### 엔딩 A: 봉쇄된 승리

조건 예시:

```yaml
human_alignment: ">= 6"
reconciliation: "< 4"
```

심연문은 파괴되고 인간 중심 항로가 복구된다. 공허종은 후퇴하지만 변경 지역에는 새로운 보복 전쟁이 시작된다.

#### 엔딩 B: 기억의 바다

조건 예시:

```yaml
void_alignment: ">= 6"
reconciliation: "< 4"
```

주인공은 기억망에 합류해 인간 함대의 공격을 막는다. 공허종은 살아남지만 주인공의 개인 기억과 인간 항로 일부가 사라진다.

#### 엔딩 C: 불완전한 휴전

조건 예시:

```yaml
reconciliation: ">= 5"
truth_fragments: ">= 4"
```

양측은 즉시 평화에 도달하지 못하지만 공동 중계망을 세우고 포로와 기억 기록을 교환한다. 일부 세력은 이탈하며 후속 갈등이 남는다.

#### 엔딩 D: 검은 항로

조건 예시:

```yaml
reconciliation: ">= 8"
truth_fragments: ">= 6"
trusted_companions: ">= 3"
stable_regions: ">= 3"
evidence_destroyed: "<= 1"
```

주인공은 심연문을 파괴하지 않고 연결 방식을 바꾼다. 강제 공유가 불가능한 제한 통로가 만들어지고 양측은 각자의 기억을 유지한 채 대화할 수 있게 된다. 가장 나은 결과지만 많은 자원과 동료의 신뢰, 지역 안정이 필요하다.

#### 엔딩 E: 반복되는 최초 접촉

조건 예시:

```yaml
truth_fragments: "< 3"
evidence_destroyed: ">= 3"
```

어느 세력이 승리하든 전쟁의 원인은 다시 은폐된다. 마지막 장면에서 새로운 세대가 상대 종족의 기습으로 전쟁이 시작됐다는 교육을 받는다.

## 15. 권장 코드 책임

| 클래스 또는 시스템 | 책임 |
|---|---|
| `StoryState` | 전역 수치, 플래그, NPC와 지역 상태 저장 |
| `QuestSystem` | 퀘스트 시작, 단계 전환, 완료 조건 평가 |
| `DialogueSystem` | 조건에 맞는 대사 선택과 결과 적용 |
| `DocumentSystem` | 문서 본문, 읽음 상태와 증거 수치 처리 |
| `WorldStateSystem` | 선택 결과를 지역 Actor와 적 배치에 반영 |
| `SaveGame` | 영구 ID 기준으로 스토리 상태 직렬화 |
| `Game` | 각 시스템의 업데이트 순서와 모드 전환 조정 |
| `Renderer` | 스토리 규칙을 알지 않고 전달받은 UI와 장면만 표시 |

스토리 조건을 `Render` 함수에서 변경하지 않는다. 상태 변경은 상호작용 처리 또는 게임 업데이트 단계에서 한 번만 수행한다.

## 16. 이벤트 처리 규칙

이벤트는 중복 실행을 막아야 한다.

```cpp
if (!storyState.HasFlag("read_erebos_medic_observation"))
{
	storyState.SetFlag("read_erebos_medic_observation", true);
	storyState.AddValue("reconciliation", 1);
}
```

- 문서를 다시 읽어도 보상을 다시 지급하지 않는다.
- 대화를 반복해도 최초 대화의 상태 변경을 다시 적용하지 않는다.
- 퀘스트 완료 이벤트는 한 번만 발생한다.
- Actor가 화면 밖으로 나가거나 지역을 다시 로드해도 스토리 상태는 유지한다.
- 저장 파일에 없는 새 플래그는 기본값 `false`, 새 수치는 `0`으로 취급한다.

## 18. 구현 우선순위

### 단계 1: 현재 첫 레벨 완성

1. `StoryState` 플래그와 정수 값 저장소 추가
2. 기존 `QuestStage`를 영구 퀘스트 ID와 단계 ID로 연결
3. 에레보스 문서 세 개에 영구 ID 적용
4. 난민 한과 의무관 일리안 대화 상태 분리
5. 스탯 배분 후 `investigate_deck` 단계 추가
6. 함교 격리문과 레벨 종료 사건 추가

### 단계 2: 외부 데이터화

1. 문서 본문을 `Game.cpp`에서 외부 파일로 이동
2. NPC 대사를 외부 파일로 이동
3. 퀘스트 목표 문구와 완료 조건을 외부 파일로 이동
4. 누락된 ID와 잘못된 참조를 시작 시 로그로 출력

### 단계 3: 선택 결과와 저장

1. 선택지 UI와 결과 명령 추가
2. NPC 신뢰와 지역 상태 추가
3. 저장과 불러오기 추가
4. 지역 재방문 시 Actor와 대사 변화 적용

## 19. 현재 범위 완료 조건

- 프롤로그부터 에레보스 제1갑판 종료까지 퀘스트 단계가 끊기지 않는다.
- 플레이어가 현재 목표를 항상 확인할 수 있다.
- 문서와 대화는 각각 한 번만 상태 값을 변경한다.
- 레벨 2와 스탯 배분 이후에도 스토리가 계속 진행된다.
- 생존자 두 명과 문서 세 개 중 일부를 놓쳐도 진행 불능이 되지 않는다.
- 필수 조사 조건은 `생존자 대화 2회 또는 문서 조사 2회`처럼 대체 경로를 허용한다.
- 레벨 종료 시 공허종을 단순한 야수로만 볼 수 없는 단서가 최소 두 개 제시된다.
- 플레이어 선택 결과를 저장할 수 있는 영구 ID가 모든 사건에 존재한다.
- 렌더러에는 퀘스트 완료나 스토리 상태 변경 로직이 들어가지 않는다.

## 20. 작성 원칙

- 대사는 한 화면에 읽을 수 있는 길이로 나눈다.
- NPC가 작품의 교훈을 직접 설명하지 않게 한다.
- 동일 사건을 문서, 환경과 NPC가 서로 다른 관점으로 말하게 한다.
- 인간의 잘못이 드러나도 공허종의 폭력이 자동으로 정당화되지는 않는다.
- 공허종의 피해가 드러나도 모든 인간을 같은 가해자로 묘사하지 않는다.
- 더 나은 결과에는 탐험, 자원, 신뢰 또는 전투 위험 같은 실제 비용이 필요하다.
- 필수 전투와 선택 전투를 구분한다.
- 스토리상 살려야 하는 NPC는 전투 Actor와 명확히 다른 진영 및 충돌 그룹을 사용한다.
- 새로운 장을 구현할 때 이 문서의 전역 상태와 엔딩 입력에 어떤 영향을 주는지 함께 정의한다.
